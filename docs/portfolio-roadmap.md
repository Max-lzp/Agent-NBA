# Deep Court 作品集整理路线

定位草案：将比赛视频、官方篮球数据和 AI 分析组合成面向不同观众的增强回放体验。

本文件是基于仓库的初步审查，不代表线上服务当前状态。目标岗位为 AI 产品经理；本人自述参与了项目大部分工作，具体职责与团队分工仍需逐项核实。

作品集优先呈现用户问题、产品决策、AI 能力边界、评测与交付，而后用架构和代码支持这些判断。案例草稿见 [portfolio-case-study.md](portfolio-case-study.md)。

## 第一版交付范围

1. **项目首页**：用问题、演示、方案、个人贡献、验证结果、局限六部分介绍项目；黑客松背景保留为项目来源。
2. **稳定演示**：提供使用已保存样例的回放入口，明确区分预生成演示与实时云端分析。默认展示有本地素材的片段；缺少视频时给出可用替代内容。
3. **技术案例**：解释视频识别、官方事件对齐、工具调用与数据校验、异步云端编排各自解决的问题，以及失败时的处理方式。
4. **可复现说明**：分别说明无需 AWS 的本地测试/演示，以及需要账号、模型权重和输入视频的完整流程。
5. **结果证据**：每项结果标注测试模式、数据来源和验证范围；补齐真实端到端验证后再更新上线状态。

## 已发现的优先问题

| 优先级 | 仓库证据 | 整理动作 | 验收方式 |
| --- | --- | --- | --- |
| P0 | `web/config.js` 默认 `examOnly: true`；README 说明没有考试片时显示生成中 | 新增适合作品集的样例模式，避免访客停在比赛占位状态 | 不配置 AWS 时可进入并播放仓库现有样片 |
| P0 | `agent/eval/report.md` 的模拟评测为 20/20，历史线上评测为 0/20 | 分开展示离线能力与线上能力；调查并重新评测真实服务 | 报告保留执行时间、模式和失败原因，禁止把模拟成绩作为上线成绩 |
| P0 | README 多处说明代码待部署 | 建立功能状态表，区分已实现、已本地验证、已部署、已端到端验证 | 每个展示功能都有对应证据；旧记录不冒充实时状态 |
| P1 | README 包含大量赛时操作和资源状态 | 首页聚焦产品和技术故事，运维与比赛记录迁入独立文档，保留历史内容 | 新读者能快速找到演示、运行步骤、贡献和局限 |
| P1 | `web/config.js` 的 GitHub 链接指向 `feat/standard-player` | 在确定作品集发布分支后统一源码入口 | 页面链接与实际发布版本一致 |
| P1 | 尚未确认个人职责 | 补充本人负责模块、关键决策、解决的问题与证据 | 清楚区分个人贡献和团队成果 |

## 建议保留的技术故事

- 识别结果与官方逐回合、赛季数据如何互相校验，以及不确定时如何减少错误标注。
- 分析师通过工具获取数据、校验人名与数字，避免生成没有来源的结论。
- 云端异步任务、冷启动与失败兜底如何影响回放体验。
- 老球迷、新球迷和带看模式如何改变信息呈现。
