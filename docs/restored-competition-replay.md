# 恢复原比赛版回放

## 展示入口

网站根路径与 `game.html` 使用原 `web/game.html`、`styles.css`、`game.js`，保留黑橙主题、原字体、观看模式、球员信息和回放组件。产品案例介绍位于 `case-study/index.html`，本地视频标记工具位于 `case-study/player.html`，二者不再替代原播放器首页。

## 本次恢复的内容

- 实际播放仓库保留的 `web/assets/flagg-replay.mp4`，约 26.55 秒，包含比赛画面、人名、数据叠加、定格回放和原有音轨。
- 保留 `web/replay/clips.js` 中弗拉格回合的分析快照，恢复 9 个原事件及 2 个成片回放导航节点。
- 点击事件跳转暂停，切换老球迷、新球迷和带看模式；显示术语、场上球员及头像、投篮数据、赛季数据与分区热区图。
- “读懂这一球”仅查询该回合的历史记录，并标注数据快照和视觉识别来源，不伪装成实时大模型问答。
- 旧 `jobId` 参数不再触发 AWS 轮询；原片单中缺失的阿门素材不进入发布清单。
- 原作品说明和架构页保留为归档资料，说明页明确区分历史 AWS 描述与当前离线能力。

## 视频与时间线对应关系

`flagg-replay.mp4` 是原管道的回放成片，不是缺失的 `flagg-broadcast.mp4`。原片约 21.49 秒，成片增加了约 5 秒的出手定格。

构建器依据 `pipeline/present/freeze.py` 的记分牌跳变算法计算插入点：原时间约 20.987 秒。原 9 个事件都发生在插入点之前，保留原时间，不能按总时长等比例拉伸。新增“出手定格回看”节点位于插入后 0.05 秒，避开编码帧边界；之后的原事件（如存在）才需要增加定格时长。

网页关闭再次自动定格，防止已带回放的视频再次倒回出手。`archive-media.json` 固定已核对视频的 SHA-256、时长与回放时长；素材变化会使构建失败，必须重新核对。编码实际总时长与理论原片加 5 秒有约 0.06 秒差异，不将这点编码差异用于拉伸事件。

传接球和身份信息沿用原视觉处理快照，可能有误差；现有回合数据不因恢复网页就视为重新核验。画面烧录的信息也不会因网页切换模式而改变，网页模式只调整网页解释和信息展示。

## 构建与测试

```bash
python3 scripts/build_archive_site.py --output /tmp/agent-nba-site
python3 -m http.server 8000 --directory /tmp/agent-nba-site
python3 scripts/qa/check_archive_replay.py
```

构建仅用 Python 标准库，不需要 AWS、npm、Docker 或模型。它按白名单复制页面、静态资源和已核对成片，不包含上传页、运维发布台、凭证或账号配置。输出目录必须位于仓库外，并带生成标记才能再次覆盖。

浏览器检查需 Playwright 和 Chromium，覆盖原主题、真实视频播放、11 个事件、跳转暂停、三种模式、球员头像、数据卡/热区图、归档解释、旧 URL、说明页返回、桌面/手机布局以及无缺失资源、无 AWS 请求。
