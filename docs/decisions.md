## D-001 最小闭环优先

- 日期：2026-10-06
- 背景：三个硬性要求（AgentCore / CloudFront / CDK）+ 12 小时赛制
- 决定：用官方 CDK 模板先打通最小闭环（约半小时），再谈创意
- 理由：官方指南原话「剩下的时间用来做那个只有你们能想出来的东西」；20:00 硬截止，部署不能留到晚上
- 影响：模拟期头半天必须完成闭环演练

## D-002 抽帧策略：2–4fps 起步

- 日期：2026-10-06
- 背景：训练视频 1080p59.94，全帧处理配额与延迟都扛不住
- 决定：抽帧从 2–4fps 起步，按识别稳定性上调；关键事件段（出手前后）局部加密
- 理由：22 秒回合里真正信息量大的瞬间有限；配额要留给 18:00 后的考试视频调优
- 影响：影响 Qwen3 VL 调用成本与事件检测精度，模拟期压测定稿

## D-003 克制呈现原则

- 日期：2026-10-06
- 背景：NBA 产品经理明确警告「不要把数据简单堆叠在视频上」
- 决定：默认画面只放轻量标注（球员名 + 1 个关键指标），深度解读藏进点击/暂停
- 理由：克制 = UX 25 分的审美分；也是与堆数据队伍的差异化
- 影响：前端交互形态定为「时间线驱动 + 分层展开」

## D-004 视觉管线采用开源组件、全部本地推理

- 日期：2026-10-07
- 背景：任务①若全靠 Qwen3 VL 逐帧识别，额度与稳定性都是风险；GPU 配额为 0
- 决定：检测+跟踪用开源方案（abdullahtarek/basketball_analysis 主干 + roboflow/sports 零件），**全部本地 CPU 推理，不调任何外部 API**；Qwen3 VL 只保留三件事：读记分牌时钟、判战术事件、兜底难帧
- 理由：开源检测跟踪在体育视频上已高度成熟，预训练权重直接可用；本地推理零 token、零外网依赖，满足 key 保护纪律；比赛日识别跑本地，只把结构化 JSON 传 S3
- 影响：Bedrock 调用量降一个数量级，18:00 后考试视频调优余量充足；球衣号码 OCR 用 Roboflow 篮球专用数据集本地跑 + 号码→花名册映射

## D-005 交付形态：视频打底、交互拿分

- 日期：2026-10-07
- 背景：硬性要求第 2 条要求 CloudFront + Web 交互界面，录屏视频不算满足；UX 25 分明写评「操作性」
- 决定：ffmpeg 预渲染成片保底（打开即看）+ Web 播放器 Canvas 叠加层做三层交互（常驻轻量 → 暂停/点击展开 → 时间线双向绑定）；演示视频照录作为提交要件和保底路径
- 理由：成片保下限，交互撑 UX 25 分和决赛视觉 40 分上限；默认画面自解释，展开层「越看越有」
- 影响：Web 前端工作量上段位，C 线（呈现线）需按「作品级 Web 应用」标准排期

## D-006 提交链接打开成片，并标明 Team ID

- 日期：2026-10-09
- 背景：组委会补充提交要求。作品页建议标注自己的 team ID。若界面是先选视频再处理（Open file 这类），评审会被拖慢；处理卡住出不来时 0 分概率大，责任也分不清。另外强烈建议在作品链接后加 `/readme`，介绍作品亮点，不求美观，有说明即可。
- 决定：门户提交的 CloudFront 链接打开的是考试视频的最终成片回放，页面上标明 Team 04。上传 / 选择文件只作为我们自己的生产入口，不作为作品 URL。同一域名提供 `/readme`，用文字说明亮点。
- 理由：评委看的是视频效果，即最终结果。打开即播，评审时间不花在等我们的流水线。`/readme` 让评委不用翻仓库也能知道作品在讲什么。
- 影响：比赛日 20:00 前提交前要核对链接落点是成片页，不是 `index.html` 上传卡片；并打开 `/readme` 确认说明在。

## D-007 P1 放进同一个栈，用开关跳过

- 日期：2026-10-09
- 背景：P1 要加 Batch、Textract、MediaConvert、CloudWatch。再拆一个栈会碰到跨栈导出。GPU 配额不够时，不能让这次部署把已经能用的分析闭环一起拖倒。
- 决定：P1 资源写在 `Team04DeepCourt` 里。`cdk deploy -c enableP1=false` 时不创建这些资源。跟踪作业由 `submit_track` 提交，`analyze_job` 不调用它。
- 理由：评分看的是模板里的资源类型。一个栈足够。开关用来在配额失败时保住 P0。
- 影响：默认部署会带上 P1。账号 10 月 10 日早上 8 点恢复后再部署。

## D-008 P2 仍在同一个栈，不设登录

- 日期：2026-10-09
- 背景：解说、追踪、密钥和快手绑定是决赛包装。比赛站点没有外人访问，不需要用户名和密码。
- 决定：不建 Cognito。上传和成品展示直接打开。P2 其余部分仍放在 `Team04DeepCourt`，`enableP2=false` 可以整段关掉。快手和飞书、GitHub 的密钥放 Secrets Manager，由 Lambda 在运行时读取。
- 理由：评委打开就能看、就能传。密钥仍然不进 Git。
- 影响：创建任务、回放页和 `/readme` 都公开。和 P1 一起挂在 10 月 10 日的 Milestone。
