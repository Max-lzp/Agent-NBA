# Deep Court｜AI 辅助 NBA 观赛

> Max-lzp 个人优化作品。延续 NBA × AWS 黑客松中的 Deep Court 项目，保留原团队来源与代码历史；本案例从我负责的个人产品优化视角展开。

## 我想解决什么问题

NBA 的观赛门槛不仅在规则，也在于观众很难把球员跑位、战术选择和统计数字连接起来。新球迷不知道该看谁、术语是什么意思；普通球迷能看出进没进，却未必理解为什么这样进攻；高阶数据则经常停留在表格里。

我的目标是把比赛画面、官方数据与 AI 解释放进同一条观看路径：帮助新球迷入门，帮助普通球迷理解战术，并让观众能够随时提问、查询有来源的数据。

这是产品要解决的问题与设计目标，尚不将理解度、留存或学习效果写成已验证收益。

## 我的职责与产品决策

我负责个人优化版本的产品定位、用户分层、交互体验、功能优先级、AI 能力边界与可用性验证，并推进回放、数据展示和项目交付。

### 1. 让信息密度适应观众

我围绕不同观看需求组织三种模式：老球迷关注数据和对位，新球迷需要术语解释，一起看模式帮助陪伴者介绍球员、延伸话题。后续通过理解任务验证模式是否有效，而不是用模式数量代替用户价值。

### 2. 让高阶数据回到具体回合

我将出手事件、预期命中率、分区热区图、球员信息与定格回放关联，让观众能将数字与画面中的选择对照。当前使用保留的比赛成片和原分析快照，不将历史数据包装成实时识别。

### 3. 让回答可追溯，而不只是流畅

我将实时提问与官方数据查询作为后续核心方向。方案通过工具调用读取官方逐回合、赛季统计和事件清单，校验人名、数字与缺失值；查不到时说明缺失。当前网站只提供历史记录查询，实时模型问答与动态官方数据查询尚未恢复。

### 4. 优先保证核心体验可用

我将比赛云资源下线后的恢复拆为阶段：先恢复真实成片和原播放器，再补齐本地标记、数据查询，后续接入识别与实时问答。已实现本地文件播放、事件标记、JSON 导出回导及不匹配数据拒绝，避免视频和事件错配。

## 技术方案

- **视频理解**：Python、YOLO + ByteTrack、Qwen3-VL、OCR；原方案使用 Rekognition 辅助识别。
- **Agent 与数据查询**：Claude Sonnet 4.6、工具调用、事件清单与官方逐回合/赛季数据；原云端实现使用 Bedrock Converse / AgentCore，目前未恢复实时运行。
- **可视化与交付**：原生 JavaScript、HTML / CSS、Canvas、FFmpeg，当前静态展示部署在 GitHub Pages。
- **历史云端架构**：S3、Lambda、API Gateway、DynamoDB、EventBridge、Step Functions、AWS Batch、TypeScript / AWS CDK。保留实现与设计记录，不作为当前实时服务宣称。

## 当前成果与能力边界

已上线真实比赛成片、11 个事件时间线节点、三种观看模式、球员信息、出手数据卡和分区热区图；辅助工具支持自选视频与人工标记。浏览器验证覆盖播放、跳转、模式、数据展示、导入导出、错误处理和手机布局。

自动战术解读、自动球员识别、实时提问及动态官方数据查询仍在迭代。未提供未经实测的准确率、用户增长、理解度提升或成本收益。

历史模拟评测为 20/20，历史线上评测为 0/20；二者描述不同条件下的结果，不能作为当前实时能力成绩。后续保留模式、数据集、来源、时间和失败原因，重新执行真实模型评测。
