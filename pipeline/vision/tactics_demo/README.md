# 七类战术识别规则 demo（供 Jason 参考）

这是独立、只读的几何规则示例，未接入视频主链路，也没有训练或评估真实视频模型。输入必须由上游提供：米制球场标定、稳定 track ID、攻防球队、逐帧球权和镜头切分。坐标原点为进攻篮筐 `(0,0)`，x 为横向、y 为篮筐向中场方向；不能把像素距离当米。

```bash
python3 pipeline/vision/tactics_demo/classify_tactics.py \
  --input pipeline/vision/tactics_demo/synthetic_horns_tracks.json \
  --output pipeline/vision/tactics_demo/synthetic_horns_output.json
python3 -m unittest discover -s pipeline/vision/tactics_demo -p 'test_*.py' -v
```

提供的输入/输出明确是 **合成牛角站位**，不是 NBA 比赛识别结果。七类候选规则都在脚本中，只有牛角合成场景做了正向示例，不宣称七类已在真实比赛达到准确率。

| 候选标签 | 当前触发条件 | 需要人工/模型复核的事实 |
|---|---|---|
| 挡拆 | 持球人与低速掩护候选 ≤2m、附近有防守者、持球人移动、掩护人随后向篮筐移动 | 是否实际阻挡防守路线、持球人是否利用掩护；合法掩护不必主动移动阻挡 |
| 手递手 | 相邻球权状态由 A 转 B，两人 ≤1.5m，B 有移动 | 近距离传球可能误触发；须观察实际交接动作和球轨迹 |
| 单打 | 一名近距离防守者，其余四名进攻者较远、没有邻近掩护候选 | 暂时站位不等于战术单打，须看持球持续与进攻动作 |
| 牛角 | 两个肘区有人，持球人居中且高于肘区 | 是站位候选，不能由身高推断两人一定是内线；后续可同时发生挡拆等 |
| 空切 | 全窗口无球、朝篮筐径向速度 ≥2m/s | 快攻跑动也可能满足；尚未验证甩开防守者或接球 |
| 无球掩护 | 低速掩护候选靠近防守者，无球队友近距离高速通过 | 必须看防守路线被阻挡，而不只是两人接近 |
| Floppy | 同镜头内，接球前 3 秒经过至少两个不同无球掩护候选，随后在底线附近获得球权 | 是较弱序列候选；真实 Floppy 可只有一个掩护，当前会漏检；也不能排除其他多掩护战术 |

窗口跨镜头、标定失效、跟踪质量不足或无法形成可靠 5v5/球权状态时跳过。没有提供虚假的“模型置信度”；输出是候选、阈值、时间和证据。多标签可以共存，不强制整回合多数票选唯一类别。

## 对原方案的修订建议

1. **投篮不中不一定结束回合**：进攻篮板后球权仍归进攻队；罚球、争球、技术犯规也要分别处理。镜头切换是观察中断，不等于球权结束。本 demo 不自行切分回合。
2. 第一阶段先识别站位与事件候选，提供人工复核；不用硬编码“掩护人移动阻挡”为标准，正常掩护经常要求静止。
3. 标定应逐镜头更新并评估重投影误差。球员脚底点比 bbox 中心更适合映射球场位置；没有标定就只显示画面坐标，不报米制距离/速度。
4. 跨镜头 track ID 不可靠时重新关联；不要把 ByteTrack 的临时 ID 当 NBA person_id。球衣 OCR + 队别 + 单场名单核验后才能绑定身份。
5. 真实验证需要逐类人工标注、镜头/比赛级训练测试隔离，报告每类 precision/recall 和混淆情况。上述阈值只是可调起点；本 demo 没有准确率承诺。
6. 时序模型、姿态估计、实时部署为后续方案，本轮没有下载模型权重或改动主链路。
