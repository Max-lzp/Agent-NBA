让每一次出手被重新讲述一遍。打开这个域名就是成片回放，不用选文件，也不用等分析跑完。

作品亮点

  1. 比分条跟着记分牌走：节次、比赛钟、客队和主队比分。出手后约三秒弹出这一球的预期命中率、区域和距离。
  2. 人名标在球衣号码对得上、而且票数够的轨迹上。对不上的人不编名字。
  3. 暂停后展开官方逐回合原文、助攻和当时场上的十个人。半场图上的点用官方坐标。
  4. 中文解说由程序根据这些事件写成，已经混进成片。当前声音是本机中文语音；Amazon Polly 开通后只换声音，不改词。

数字从哪来

事件不由模型看图编造。记分牌读出节次、比赛钟和比分；追踪给出人和框；官方逐回合补上投篮人、助攻和预期命中率（xFG）。AgentCore 只取回并校验这份清单。

决策反差是二次加工，不是另一套数据：预期命中率低于四成却进了，标成英雄球；高于六成却没进，标成可惜。其余出手只显示预期命中率本身。

引力和胜率摆幅没有逐回合来源，画面上不出现。

数据管道

本地追踪写出结构化清单，上传到 S3 structured/。Lambda 调 Bedrock AgentCore 校验；Agent 不可用时 Lambda 直接读清单，回放不会停住。页面通过 CloudFront 打开成片。上传入口在 /index.html，只给我们自己用。

  1. 收片：浏览器经 CloudFront、API Gateway、Lambda 把视频直传到 S3，任务记在 DynamoDB。本地命令也可以直接读文件。
  2. 追踪和记分牌：YOLO、ByteTrack、RapidOCR 在本地跑。记分牌不走 Textract。
  3. 事件清单在本地生成，再用本地的官方逐回合数据补出手人、助攻和预期命中率。独行侠的出手还会按当时分差，带上 2025-26 赛季效率。
  4. 清单放到 S3。Lambda 调 Bedrock AgentCore 校验，页面事件写入 DynamoDB。
  5. CloudFront 打开回放。两句解说可以交给 Bedrock 写；现在混进成片的声音仍是本机中文语音。Polly 已接通，还没替换这段声音。
