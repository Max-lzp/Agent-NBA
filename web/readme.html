NBA × AWS Broadcast Code 12 · Team 04

Team 04 · Deep Court 作品说明

让每一次出手被重新讲述一遍——用深度数据驱动的 AI，把一段比赛录像变成带数据叠加和解说的可交互成片。

打开提交域名就是考试片的最终成片回放，评委不用选文件、也不用等分析跑完。本页按评分标准逐项说明：做了什么、数据从哪来、准不准、用了哪些 AWS 服务、多快、怎么复现。

01作品亮点

打开即看提交的 CloudFront 根路径直接播最终成片，不点任何交互也成立；深度解读藏在暂停和时间线里，越看越有。
比分条跟着记分牌走节次、比赛钟、客队与主队比分实时同步。出手后约 3 秒弹出这一球的预期命中率（expected FG，xFG）、区域和距离。
人名标在人身上球衣号码识别对上场名单（roster），把名字写在球员身上，不是堆一张表格。认不出就只写「火箭球员 / 独行侠球员」，绝不编名字。
暂停展开官方记录暂停后展开官方逐回合（play-by-play）原文、助攻和当时场上的十个人；半场图上的落点用官方坐标。
进球定格回看进球后画面跳回出手帧定格 5 秒：投篮人脚下画红圈，领防人脚下画黄色虚线圈、名签贴在他躯干旁背向投篮人一侧，弹出两人的队内排名星级，以及这一投所在区的对手命中率（越低越好）、投篮人同区命中率和身高/位置/选秀等资料；右栏是分区热区图，红圈标出这一投。定格卡不烧比分条。
中英文双音轨播放器可切英文原声或中文解说。中文是整段英文解说经转写、翻译后，用 Amazon Polly 知语合成的译制音轨，不是只写两句。

02从输入到输出：完整流程

输入 INPUT

一段比赛进攻回合录像（上传视频文件，或粘贴比赛 URL；本地也可直接读文件）。

输出 OUTPUT

一段烧好记分牌的成片，叠加人名与出手数据、可点的时间线、进球定格回看、中英文双音轨——打开即看的深度回放页。

1
追踪 TrackingUltralytics YOLO11 检测人和球，ByteTrack 跟踪保持球员 ID，产出每帧的人、球轨迹。
2
记分牌识别 Scoreboard OCR读节次、比赛钟、进攻钟（shot clock）和比分——这是转播方给的、几乎不会错的「免费真值」。
3
认人 Identity把清楚的轨迹帧交给 Qwen3 VL（经 Bedrock）读号码和球衣颜色、多帧多数票，Amazon Rekognition 读数算第二票；号码只在此刻场上同队 5 人里对，对不上就不写名字。
4
事件流 Events按球在谁脚下写出持球、传球、出手、回合；用球路找脱手那一帧，并回溯贴住投篮人最久的对方球员作为领防人。
5
官方数据补全 Enrich用记分牌比分对上是哪一场官方比赛，补上投篮人、助攻、预期命中率、出手坐标和当时场上十人。
6
校验与成片 Verify & Render结构化清单上传 S3，Lambda 调 Bedrock AgentCore 校验后写入 DynamoDB；FFmpeg 把记分牌烧进成片，再做中英文音轨。
7
回放 PlaybackCloudFront 播放器按任务号取回事件，画到时间线和画面叠加层上，供评委交互。

一条纪律：事件只来自上面这份结构化清单，不让任何模型凭画面「编」出比赛事件。认人用 Qwen3 VL 读球衣号码和颜色，属于识别、不生成事件；早期抽帧问视觉大模型「发生了什么」的做法准确率低，已停用。

03数据从哪来，怎么保证准确

三个数据来源

  • 追踪：给出画面里每个人、球的框和轨迹（谁在哪、谁离球近）。
  • 记分牌识别：给出节次、比赛钟、进攻钟和比分，是画面里最可信的信号。
  • 官方逐回合数据：赛季固定是火箭（HOU）对独行侠（DAL）；用记分牌比分对上官方记录后，补出投篮人、助攻、预期命中率、出手坐标和场上阵容。

怎么保证准确

  • 记分牌当真值。画面里球真正被检测到的帧只有约四成，球衣颜色在贴身防守时会把人分错队；但记分牌数字几乎不会错。进攻钟不重置就不换球权，比分跳变要连续读到 2 次、且只有一边加 1–3 分才确认——靠这两条规则把误读挡掉。读记分牌后，进攻方判对率从约四成提升到接近 100%。
  • 号码宁缺勿错。考试片把清楚的轨迹帧交给 Qwen3 VL 多帧投票读号码和球衣颜色，Rekognition 读数作第二票，Textract 仅在调用失败时兜底；号码只在此刻场上同队 5 人里比对，对不上只写「某队球员」，同一个名字只留票数最多的一条轨迹，官方逐回合的得分人、助攻人先钉。训练片仍用本机 8 帧投票、第一二名票数持平就弃权。
  • 对上官方比赛才补数据。用记分牌比分比对四场已下载的官方比赛，对上了才回填投篮人、助攻和预期命中率；对不上就只保留画面能确定的信息。
  • AgentCore 只校验、不编造。Bedrock AgentCore 负责取回并校验这份清单，不调模型生成事件；它不可用时 Lambda 直接读清单，回放不会停住。

「英雄球 / 可惜」等反差标签是在预期命中率上的二次加工（低于四成却进 = 英雄球，高于六成却没进 = 可惜），不是另一套数据。引力、关键度来自官方赛季汇总，页面上会标明不是这一球的胜率变化。

04用了哪些 AWS 服务

区域统一 us-east-1，一个 CDK 栈 Team04DeepCourt。状态如实标注：主路径 评委这条链路；已接通 云上已跑通但不是训练片默认路径；本机 仍在本地做。考试片的认人、事件清单、官方数据和解说已接到云上作业；训练片的领防、脱手帧、分差效率和队内排名仍在本机。

环节AWS 服务做什么状态
收片 / 任务CloudFront、API Gateway、Lambda create_job、S3 raw/、DynamoDB浏览器经预签名地址把视频直传 S3，任务状态记进 DynamoDB，录像不进应用服务器。主路径
追踪AWS Batch、EC2 c7i.48xlarge、EBS、ECR、S3GPU 配额为 0，改用标准配额最大的 CPU 实例（192 vCPU）跑检测与跟踪，机器保持开着不等开机。已接通
记分牌同一台 c7i.48xlarge 上的 RapidOCR读节次、比赛钟、进攻钟和比分（本地 OCR 库，不走 Textract）。已接通
认人Bedrock Converse（Qwen3 VL）、Amazon Rekognition DetectText、S3 official/ 与 identity/（Textract 仅兜底）考试片把轨迹帧交给 Qwen3 VL 多帧投票读号码和球衣颜色，Rekognition 第二票，只在场上同队 5 人里对；训练片仍用本机回溯认人。已接通 / 训练片本机
事件清单S3 structured/、Lambda analyze_job、Bedrock AgentCore、DynamoDB考试片按持球写接球和传球、对上官方出手，清单写进媒体桶；领防与脱手帧仍在本机。已接通 / 领防本机
官方数据S3 official/（逐回合、shot quality）用节次、比赛钟和比分对上是哪一场，补命中、助攻、预期命中率；分差效率、引力、队内排名仍在本机。已接通 / 对位本机
校验Lambda analyze_job、Bedrock AgentCore DeepCourtAnalyst、DynamoDB、CloudWatch Logs取回并校验清单写成页面事件；Agent 不可用时 Lambda 直接读清单兜底。主路径
回放接口API Gateway、Lambda get_job / list_events播放器按任务号查状态和事件，驱动时间线与叠加层。主路径
解说Amazon Transcribe、Translate、Polly Neural 知语（Zhiyu）、S3成片之后把英文原声转写、译成中文，按原句时间合成中文音轨；探测片的中文音轨已经能播。已接通
成片转码FFmpeg（在 c7i 上）、MediaConvert 模板把记分牌烧进成片、原声留在里面；MediaConvert 模板已建，尚未提交转码作业。已接通
网页呈现CloudFront Site、S3 网页桶、CloudFront Function根路径打开播放器，/readme 指到本页，/api/* 转到 API Gateway；网页桶不公开，只经 OAC 读取。主路径
观测 / 密钥CloudWatch、X-Ray、Secrets Manager、Cost Explorer看吞吐、延迟与限流；密钥由 Lambda 运行时读取，仍是空占位，不进仓库。已接通

三项硬性要求均满足：分析编排跑在 Bedrock AgentCore、作品以 CloudFront 发布且具备 Web 交互界面、基础设施用 AWS CDK（TypeScript）写成。本页与仓库 docs/pipeline-map.md 是同一张图。

05数据管道图

颜色：云上作业（考试片主路径）本机（训练片深度字段）

A
浏览器 → CloudFront → API Gateway → Lambda建任务，返回 S3 预签名地址，浏览器把录像直传到 raw/。
B
c7i.48xlarge：追踪 + 记分牌 + Qwen3 VL 认人同一台机器出轨迹、读记分牌，用 Qwen3 VL（Rekognition 第二票）认号码，并从 S3 的官方逐回合对上比赛，写出结构化清单。
C
S3 structured/ → Lambda analyze_job → Bedrock AgentCore → DynamoDB清单上云触发校验，事件写入 DynamoDB。
D
成片 → Transcribe → Translate → Polly 知语FFmpeg 烧记分牌出成片；英文原声转写、翻译后合成中文音轨。
E
CloudFront 播放器按任务号取回 DynamoDB 事件，画到时间线和叠加层，提供英文 / 中文双音轨。
L
本机：训练片深度字段领防人、脱手帧、分差效率、引力与队内排名仍在本机算，再随训练片成片一起呈现。

06处理速度

约 5 分钟

一段 20 多秒的新进攻回合，从拿到视频到出结构化清单（谁持球、谁传谁、谁投、进没进、预期命中率、场上阵容）的目标用时。

约 130–150 秒

追踪与记分牌识别并行的耗时（M 系列 Mac 实测）；认白衣、建清单各几秒，认比赛加官方补全约 1 秒。

抽帧从 2–4 fps 起步、出手前后局部加密，把算力用在信息量大的瞬间。云上追踪的 c7i.48xlarge 保持 192 vCPU 开着，下一支片子不用等开机。

07如何复现

只看网页（最快）

# 在仓库 web/ 目录起一个静态服务器
cd web && python3 -m http.server 8000
# 浏览器打开播放器与说明页
open http://localhost:8000/game.html      # 成片回放（提交链接的内容）
open http://localhost:8000/readme.html    # 本页

注：成片 mp4 在部署的网页桶里，本地仅起服务器时视频可能不显示，页面布局与数据叠加逻辑可照常查看。

跑一段新视频的完整管道

python3 -m pipeline.run_clip --video "<考试视频>.mp4" --clip exam
python3 -m pipeline.present --clip exam
open web/game.html?clip=exam              # 比分条和出手卡烧进成片，人名在页面上跟着框走

部署到 AWS（profile nba，us-east-1）

cd cdk && npm install && npx cdk synth
npx cdk deploy Team04DeepCourt -c enableP1=false -c enableP2=false --profile nba
