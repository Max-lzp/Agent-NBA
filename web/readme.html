Deep Court

让每一次出手被重新讲述一遍。打开这个域名就是成片回放，不用选文件，也不用等分析跑完。

作品亮点

  1. 比分条跟着记分牌走：节次、比赛钟、客队和主队比分。出手后约三秒弹出这一球的预期命中率、区域和距离。
  2. 这一回合场上 10 个人先对上身体：号码、持球和领防是钉子，剩下的人只在同队还空着的坑里排除。成片前 3 秒标出已经对上的人，之后只标持球人、传球双方和领防人。两个差不多高、又没有号码的坑先空着。
  3. 暂停后展开官方逐回合原文、助攻和当时场上的十个人。半场图上的点用官方坐标。
  4. 播放器可以选英文原声或中文解说。中文是整段英文解说的译文，用 Polly 的知语说出来，不再只写两句，原解说也不留在这条音轨里。

数字从哪来

事件不由模型看图编造。记分牌读出节次、比赛钟和比分；追踪给出人和框；官方逐回合补上投篮人、助攻和预期命中率（xFG）。AgentCore 只取回并校验这份清单。

决策反差是二次加工，不是另一套数据：预期命中率低于四成却进了，标成英雄球；高于六成却没进，标成可惜。其余出手只显示预期命中率本身。

引力和关键度来自官方赛季汇总。暂停后写在该球员这一球旁边，标明不是这一球的胜率变化。

数据管道

本地追踪写出结构化清单，上传到 S3 structured/。Lambda 调 Bedrock AgentCore 校验；Agent 不可用时 Lambda 直接读清单，回放不会停住。页面通过 CloudFront 打开成片。上传入口在 /index.html，只给我们自己用。

  1. 收片：浏览器经 CloudFront、API Gateway、Lambda 把视频直传到 S3，任务记在 DynamoDB。本地命令也可以直接读文件。
  2. 追踪和记分牌：考试片交给 Batch，机器是保持开着的 c7i.48xlarge。同一台机器读记分牌，再用 ffmpeg 把比分烧进成片，直接放进网页桶。训练片仍可以在本机用 MPS 出片。记分牌检测边长限制在 640；球衣号码的裁切限制在 192。不走 Textract。
  3. 事件清单在本地生成，再用本地的官方逐回合数据补出手人、助攻和预期命中率。独行侠的出手还会按当时分差，带上 2025-26 赛季效率。对得上的人再带上赛季出手质量、引力和关键度。每次出手还会找到球离手那一帧，记下投篮人。再从出手往前看 5 秒，跟住投篮人，贴他最久的对方球员就是领防人。号码只在当时在场的人里认，读不准就写「号码没读出」，不拿对位表顶替。投篮人和领防人还会带上队内排名：得分、命中率、抢断、盖帽、防守效率等，队内第 1 名五星，每往后一名少半星。
  4. 回放时，进球后画面跳回出手那一帧，定格 5 秒：投篮人脚下画红圈，领防人脚下画黄色虚线圈；卡片写当时比分、投篮人和领防人的队内排名星级；认出领防人才写他的名字、本场对位和赛季场均。右栏是投篮人的分区热区图，红圈标出这一投，并写出这个位置的预期命中率。
  5. 清单放到 S3。Lambda 调 Bedrock AgentCore 校验，页面事件写入 DynamoDB。
  6. 英文音轨是原声。中文音轨先转写英文解说，再译成中文，用 Polly Neural 知语按原句时间合成。播放器上自己选。
  7. 网页呈现：CloudFront 根路径打开播放器 game.html。作品说明在 /readme。上传页只给我们自己用。
