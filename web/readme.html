Deep Court

让每一次出手被重新讲述一遍。打开这个域名就是成片回放，不用选文件，也不用等分析跑完。

作品亮点

  1. 比分条跟着记分牌走：节次、比赛钟、客队和主队比分。出手后约三秒弹出这一球的预期命中率、区域和距离。
  2. 这一回合场上 10 个人先对上身体：号码、持球和领防是钉子，剩下的人只在同队还空着的坑里排除。成片前 3 秒标出已经对上的人，之后只标持球人、传球双方和领防人。两个差不多高、又没有号码的坑先空着。
  3. 暂停后展开官方逐回合原文、助攻和当时场上的十个人。半场图上的点用官方坐标。
  4. 播放器可以选英文原声或中文解说。中文是整段英文解说的译文，用 Polly 的知语说出来，不再只写两句，原解说也不留在这条音轨里。

数字从哪来

事件不由模型看图编造。记分牌读出节次、比赛钟和比分；追踪给出人和框；官方逐回合补上投篮人、助攻和预期命中率（xFG）。AgentCore 只取回并校验这份清单。

决策反差是二次加工，不是另一套数据：预期命中率低于四成却进了，标成英雄球；高于六成却没进，标成可惜。其余出手只显示预期命中率本身。

引力和关键度来自官方赛季汇总。暂停后写在该球员这一球旁边，标明不是这一球的胜率变化。

数据管道

考试片在云上写出结构化清单，上传到 S3 structured/。Lambda 调 Bedrock AgentCore 校验；Agent 不可用时 Lambda 直接读清单，回放不会停住。页面通过 CloudFront 打开成片。上传入口在 /index.html，只给我们自己用。

  1. 收片：浏览器经 CloudFront、API Gateway、Lambda 把视频直传到 S3，任务记在 DynamoDB。本地命令也可以直接读文件。部署之后，raw/ 上传由 EventBridge 启动一条 Step Functions，只提交一次 Batch。
  2. 追踪和记分牌：考试片交给 Batch，机器是保持开着的 c7i.48xlarge。状态机等到这台机器跑完，再让 Lambda 调 AgentCore 校验。同一台机器读记分牌，再用 ffmpeg 把比分烧进成片，直接放进网页桶。训练片仍可以在本机用 MPS 出片。记分牌检测边长限制在 640。
  3. 认人、事件和官方数据：考试片在同一台机器上把轨迹帧交给 Qwen3 VL 读号码和球衣颜色，多数票定人；Rekognition 算第二票。裁判先排除。号码只在球衣颜色那一队这一刻的场上 5 人里对，同一个名字只留一条轨迹，并从这条轨迹的第一帧挂到结尾。分得出队但没有名字的人，标签只写 Agent detecting，颜色用队色；分不出队的不挂。官方逐回合的得分人、助攻人先钉。按持球写出接球和传球；从 S3 的官方逐回合对上是哪一场，比分跳动时补上命中、助攻和预期命中率。清单写到 structured/。训练片的领防、脱手帧、分差效率和队内排名仍在本机。
  4. 回放时，进球后画面跳回出手那一帧，定格 5 秒：投篮人脚下画红圈，领防人脚下画黄色虚线圈，领防名签贴在他躯干旁、背向投篮人一侧；卡片写投篮人和领防人的队内排名星级（定格卡不再烧比分条）；认出领防人才写他的名字、本场对位和赛季场均。右栏是投篮人的分区热区图，红圈标出这一投，并写出这个位置的预期命中率。
  5. 清单放到 S3。部署之后由状态机调用 Lambda，Lambda 再调 Bedrock AgentCore 校验，页面事件写入 DynamoDB。分析师把解说写到 S3 analysis/。校验完，状态机核对成片和片单，并只失效这一支片子的路径。
  6. 成片之后才做音轨。英文是原声。中文把这条原声转写、译成中文，用 Polly Neural 知语按原句时间合成。播放器上自己选。探测片的中文音轨已经能播。
  7. 网页呈现：CloudFront 根路径打开播放器 game.html。作品说明在 /readme。上传页只给我们自己用。
